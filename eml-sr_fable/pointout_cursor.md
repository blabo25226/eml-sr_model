前回までのコードレビューとテスト結果を踏まえ、Feynman 以外の多様なデータに eml-sr_fable を当てたときの欠点と、優先度付きの修正方針を整理します。

全体像：何が「汎用」で何が「特化」か
現状の強みは 3層のハイブリッド です。

Stage A（辞書 + 変換）  ← 物理式向けの閉形式ソルバ（強いバイアス）
Stage C（比分解）       ← y = M(x)·g(x) 仮定
Stage B（BFS, cplx≤6）  ← 比較的汎用な木探索
Feynman で 80% を出しているのは主に Stage A/C の功績です。一般データでは Stage B だけが実質の探索エンジン になるケースが多く、そこは max_complexity=6・ビーム幅 1000 というかなり厳しい制約です。

欠点と修正点（カテゴリ別）
1. データ前提の硬さ
欠点	内容	一般データでの問題
usable_variables
全サンプルで変数 > 1e-12 を要求
ゼロ近傍・負値・符号混在データで Stage A が無効化
ターゲット変換
Log/InvY は「全正 or 全負」が必要
正負混在の $y$ では変換の半分が使えない
ノイズ未対応
ベンチは厳密 $y$、RMSE < 1e-4
実測データでは過適合・スプリアス項が増える
修正案

変数ごとに シフト・符号変換（$x' = |x| + \epsilon$, $\mathrm{sign}(x)\cdot\ln(1+|x|)$ 等）を前処理として自動選択
負の $y$ 向けに piecewise 変換（正負で別フィット、または $y = s \cdot |y|$ と符号分離）
ノイズ付きベンチを標準化：$y \leftarrow y + \mathcal{N}(0, \sigma^2)$、$\sigma$ を SNR でスイープ
OMP の辞書選択に BIC / MDL / 交差検証 を導入（訓練 RMSE だけで項を増やさない）
2. Stage A 辞書の形が先に決まっている
欠点	内容
Feature が固定
sin, cos, ln, cos$(x_i-x_j)$, $(x_i-x_j)^2$ 等のみ
2変数相互作用まで
3変数以上の積の三角（$\sin(x_1 x_2 x_3)$ 等）は非対応
辞書サイズ
最大 15万列 → 変数数・サンプル数が増えると破綻 or 過適合
complexity 無制限
BFS は cplx≤6 なのに Stage A は 100 超の式も「成功」
一般データで起きること

真の構造が $\tanh(x_1+x_2)$, $|x_1-x_2|$, $\mathrm{sgn}(x)$, 有理式 $P/Q$ など 辞書外 → Stage A が junk な Plus 連鎖で近似
化学・生物・経済データの典型的な形（ロジスティック、ガンマ分布、スプライン的形）に弱い
修正案（優先度順）

Stage A に complexity / 項数ペナルティを導入（BFS と同様に MDL で候補をランク）
辞書の動的生成：データから候補 Feature を学習（例：相関の高いペアにだけ cos$(x_i-x_j)$ を追加）
有理関数ステージの追加：$y \approx P(x)/Q(x)$ を分子・分母それぞれ OMP（レポート §9.3 でも I.16.6, I.18.4 向けに言及）
辞書を段階的に拡張（小さい辞書 → 失敗時だけ大辞書）で計算量と過適合を抑制
レポートでは 「BFS complexity」と「Stage A 実効 complexity」を分離表示
3. ターゲット変換が6種類に固定
変換	想定している形	一般データで不足する例
Log
$e^{\sum}$
$\ln(\sum)$, べき乗以外の非線形
InvY2
Lorentz 型
$y^2 = \sum$ 以外の暗黙関数
Log1p
$e^m-1$
ロジスティック、シグモイド
修正案

変換の自動選択を情報量基準で行う（今は全変換を総当りだが、候補自体が固定）
Box-Cox / Yeo-Johnson 的な 一般化された冪変換 を追加
暗黙関数 $F(x,y)=0$ 向けに $y$ ではなく残差 $F(x,y)$ を最小化するステージ
4. 比探索 Stage C の仮定
$y = M(x) \cdot g(x)$ は物理の積分解に効くが、一般には：

純和 $f(x) + g(x)$ には無効
$M$ の推定が外れると比 $r = y/M$ が発散し全滅
ホワイトナー候補5つでも不十分なケースあり
修正案

加法的分解 $y = a(x) + b(x)$ の対偶ステージ（それぞれに OMP）
比探索の前に 加法/乘法のどちらが良いか を簡易モデル選択
ホワイトナー失敗時の フォールバック（Stage C をスキップして BFS に直行 — 既にあるがもっと積極的に）
5. BFS（Stage B）単体の表現力不足
一般データで Stage A/C が効かない場合、残るのは cplx=6, beam=1000 の BFS だけです。

欠点	影響
max_complexity=6
深い入れ子（$\sin(e^{x^2})$ 等）に届かない
時間予算 110s/式
変数が多いと探索空間が爆発
subsample 256
高次元・非単調データでスコアが外れる可能性
アフィンスケーリング
定数・スケールは吸収できるが構造は伸ばせない
修正案

用途別に 2.test 相当の緩和設定を一般ベンチの標準に
段階的 complexity 増加（6→8→10 と予算内で自動エスカレーション）
変数数に応じた ビーム幅・時間の自動スケーリング
Stage A 失敗時は BFS の complexity 上限を 一時的に引き上げる連携
6. 評価・成功判定の問題
現状	問題
ok = 訓練 RMSE < 1e-4
記号回収ではなく数値一致
訓練＝評価（750点同一）
過適合を検出できない
junk 項付き高 complexity も ok
III.14.14 cplx=106 など
修正案

ホールドアウト / K-fold を標準評価に組み込む
記号簡約度（項数、depth、係数の「きれいさ」）を第二指標に
ok を二段階に：数値 ok と 構造 ok（簡約後に真式と等価、または項数・complexity 上限内）
ノイズベンチでは RMSE 閾値を $\sigma$ に比例させる
7. 計算コスト・スケーラビリティ
要因	ボトルネック
15万列 OMP
変数 $\ge$ 6 で辞書爆発
Pass 2 は全変換×全辞書
式ごとに数十秒〜80秒超
並列は Rust 内のみ
99式を逐次実行
修正案

変数数・サンプル数に応じた 辞書サイズの自動キャップ
Stage A の 早期打ち切り（Pass 1 で ok なら Pass 2 スキップ — 既にあるが閾値の調整）
式レベルの 並列ベンチ（Python 側）
大規模データ向け ミニバッチ OMP（全データではなくストリーミング残差）
8. EML フレームワークとしてのギャップ
研究の枠組みは「EML状の木」ですが、勝ち式はほぼ Exp/Log/Sin/... で、EML 演算子の優位性は未検証です。

修正案

BFS で EML 優先展開（$\exp(x)-\ln(y)$ 型を1ノードで表現）するバイアス
Stage A に EML 型の辞書列（例：$\mathrm{EML}(g(x), h(x))$ の組）を追加
EML を使う式と使わない式の 比較ベンチを別途設計
優先度付きロードマップ
実装コストと汎用性への効果で並べると、おすすめは次の順です。

短期（評価の正直化・リスク可視化）

「様々なデータに適用する」ための本質的な修正は、Stage A/C の物理特化を 「失敗時にだけ使う強力なヒューリスティック」 に格下げし、同時に (1) ノイズ・外挿に強い評価、(2) Stage A の complexity 制御、(3) 辞書外の形（有理式・ロジスティック等）へのステージ追加、の3点だと思います。

Feynman 精度を落とさず汎用性を上げるなら、まず ノイズベンチ + 非Feynman 小セット で現状のどこが壊れるかを測るのが安全です。必要なら、そのベンチ設計とスクリプト案まで具体化できます。
