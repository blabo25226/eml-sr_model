### 1.2 first_AI のアルゴリズム概要（調査結果）

```

  ├─ 各レベル: 単項演算子適用 + 二項演算子の組合せ

  ├─ Beam Search（beam_width で打ち切り）
```

## 2. 確定方針（ユーザー指示・2026/07/03）

| # | 項目 | 方針 |
|---|------|------|
| 1 | **MAX_COMPLEXITY** | **7 に拡張**（実行時間増を許容） |
| 2 | **定数の扱い** | $\pi$, $e$, $1/2$ 等を **記号として回収する必要はない**。`Param(C)` 等の最適化により $3.1$, $2.7$, $0.5$ 等の **数値近似** が得られ、RMSE 閾値を満たせば合格とする |
| 3 | **評価プロトコル** | **cursor 専用のハイパーパラメータを許容**する。first_AI との比較はベースライン参照として行い、同一設定である必要はない |
| 4 | **優先順位** | **特定式の優先なし**。Feynman 99式全体で回収数を最大化する |

### 2.1 定数近似の合格基準

回収判定は **数式の記号形ではなく RMSE** で行う（既存プロトコルと同様）:

- **ok:** RMSE $< 10^{-4}$
- **partial:** RMSE $< 10^{-2}$

定数に関する追加ルール:

- 真の式が $1/2 \cdot k x^2$ で、発見式が $0.498 \cdot k x^2$（`Param` 最適化結果）→ **ok としてカウント**
- 真の式が $\pi r^2$ で、発見式が $3.14 \cdot r^2$ → **ok としてカウント**
- $\mathrm{Exp}(\mathrm{Param})$ や $\mathrm{Times}(\mathrm{Param}, v)$ 等、構造は異なっても数値誤差が閾値内なら合格

実装では **記号定数（ConstOp）のシードは必須としない**。`Param` の多様な初期値・多スタート最適化（Phase B/C）で数値近似を獲得する方針とする。

### 2.2 cursor 専用デフォルト設定（案）

## 3. eml-sr_model_cursor の設計方針

### 3.1 基本コンセプト

`eml-sr_model_first_AI` の Rust アーキテクチャ（BFS + EML + Beam + Pareto）を維持しつつ、**Feynman ベンチマークで観測された失敗パターンに対応する差分改善** を `eml-sr_model_cursor/` に実装する。

- Python モジュール名: `eml_sr_model_cursor`
- 評価スクリプト: `src/feynman_eml_sr_model_cursor.py`（cursor 専用設定を反映）
- first_AI との比較: 回収数・変数数別成功率等を **参照指標** としてレポートに記載（設定差は明記）
- 変更は段階的（フェーズごとにベンチマークし、**全体 ok_count が増えた** 改善のみマージ）

### 3.2 非目標（スコープ外）

- ニューラルネット・遺伝的プログラミング等の別パラダイムへの置換
- Feynman 全99式の完全回収（現実的に困難な 9変数式等は中期対象外）
- `AGENTS.md` で言及の PDF 原著論文（リポジトリ内に未配置）への依存

### 3.3 演算子拡張の検討結果（2026/07/03）

Feynman CSV 130式の `Formula` 列を集計し、first_AI の演算子セットと `value.rs` の未登録実装を照合した。

#### 3.3.1 Feynman 式における演算パターン頻度

| パターン | 出現回数（式内） | first_AI での表現 | ギャップ |
|---------|----------------|------------------|---------|
| `**2` | **79** | `Times(v,v)`（複雑度+2） | **大** → `Square` が必要 |
| `sqrt` | 18 | `Sqrt` ✓ | なし |
| `sin` / `cos` | 各11 | `Sin` / `Cos` ✓ | なし |
| `exp` | 10 | `Exp` ✓ | なし |
| `**3` | 5 | `Times(Times(v,v),v)`（+3） | **中** → `Cube` が有効 |
| `**4` | 2 | さらに冗長 | `Pow` または `Square` の組合せ |
| `**5` | 1 | 同上 | 同上 |
| `ln` | 1 | `Log` ✓ | なし |
| `tanh` | 1 | `Exp`+`Neg` で近似可能 | 小（後述） |
| `abs` | 0 | — | 距離は `sqrt(x²+y²)` 型が主 |

**結論:** 演算子追加の ROI は **冪乗系（Square / Cube / 制限付き Pow）** に集中する。三角・指数・対数・平方根は既存でカバー済み。

#### 3.3.2 追加推奨演算子（採用）

| 優先度 | 演算子 | 型 | 定義 | 根拠 |
|--------|--------|-----|------|------|
| **A-1 必須** | `Square` | 単項 | $x^2$ | `**2` が最多。`I.14.4`, `II.3.24`, `II.8.31`, Gaussian 等 |
| **A-2 必須** | `Cube` | 単項 | $x^3$ | `r³` 分母（`I.12.2`, `I.12.4`, `II.6.15b` 等）。`Times(Square(v),v)` より複雑度1節約 |
| **A-3 必須** | `Pow` | 二項（**制限付き**） | $a^b$ | `**4`, `**5`, `omega**4` 等。`value.rs` の `c_pow` を利用 |

**Pow の探索制限（探索空間爆発の防止）:**

一般の `Pow(任意の部分木, 任意の部分木)` は BFS の分岐が急増する。cursor では次のいずれかで実装する:

- **案1（推奨）:** 第2引数 $b$ を `Param` ノードまたは小さな定数リテラルのみに制限（指数は数値最適化で $2,3,4$ 等を学習）
- **案2:** 第2引数を整数定数 $\{2,3,4,5\}$ のみに制限し、一般 `Pow` は将来拡張

いずれも「底 $a$ は任意の部分木、指数は学習可能スカラー」という Feynman の典型パターン $v^2$, $r^3$, $\omega^4$ に合致する。

#### 3.3.3 追加見送り・任意演算子（不採用または低優先）

| 演算子 | `value.rs` | 判断 | 理由 |
|--------|-----------|------|------|
| `Abs` | 未実装 | **Phase A では見送り** | Feynman 式に `abs(` の直接使用なし。距離は `Sqrt(Plus(Square(...),...))` で表現可能 |
| `Tanh` | `c_tanh` あり | **低優先・効果測定後** | 対象は `II.35.21` の1式のみ。全99式への探索コスト増が上回る可能性 |
| `Sinh` / `Cosh` | あり | **見送り** | `exp(x)±exp(-x)` は既存 `Exp`+`Neg` で表現可能（`II.35.18` 等） |
| `ArcSinh` 等 | あり | **見送り** | Feynman に出現なし |
| 専用 `Gaussian` / `Lorentz` | — | **見送り** | ドメイン特化すぎる。汎用演算子 + 複雑度7で対応 |
| `Hypot`, `SumSquares` | — | **見送り** | 同上 |

`Tanh` は Phase A コア（Square/Cube/Pow）のベンチマーク後、実行時間に余裕がありかつ `II.35.21` が依然失敗の場合のみ **Phase A+** として追加検討する。

#### 3.3.4 cursor 完成時の演算子セット（予定）

**既存16種** + **Square, Cube, Pow（制限付き）** = **19種**（+ Tanh は任意で20種）

```
EML, Neg, Inv, Plus, Times, Subtract, Divide,
Exp, Log, Sqrt, Sin, Cos, Tan, ArcSin, ArcCos, ArcTan,
Square, Cube, Pow   ← 新規
```

## 4. 改善項目（優先度順）

### Phase A: 演算子拡張（期待効果: 大）

§3.3 の検討に基づき、**Square + Cube + 制限付き Pow** を必須実装とする。

#### A-1. `Square` 単項演算子（必須）
- 定義: $\mathrm{Square}(x) = x^2$
- 実装: `value.rs` に `c_square` を追加（`c_pow(z, real(2.0))` のラッパーでも可）
- **根拠:** Feynman 式中 `**2` が79回。`Pow(v,C)` より複雑度1節約
- 複雑度カウント: 単項として `Sqrt` と対称に扱う

#### A-2. `Cube` 単項演算子（必須）
- 定義: $\mathrm{Cube}(x) = x^3$
- 実装: `c_pow(z, real(3.0))` のラッパー
- **根拠:** `**3` が5回、$1/r^3$ 型の分母が複数。`Times(Square(v), v)` より複雑度1節約

#### A-3. `Pow` 二項演算子（必須・制限付き）
- `value.rs` の `c_pow` を利用
- 定義: $\mathrm{Pow}(a,b) = a^b$
- **制限:** 第2引数 $b$ は `Param` または定数ノードのみ（§3.3.2 案1）
- **根拠:** `**4`, `**5`, $\omega^4/(\omega^2-\omega_0^2)^2$ 等の高次冪

#### A-4. `Tanh` 単項演算子（任意・Phase A+）
- `c_tanh` は `value.rs` に実装済み
- **条件付き:** Phase A コア完了後のスモークテストで実行時間増 $< 20\%$ かつ `II.35.21` が失敗のままの場合のみ追加
- 対象1式のためデフォルトでは **実装しない**

#### A-5. 見送り演算子
- `Abs`, `Sinh`, `Cosh`, 双曲逆関数, ドメイン特化演算子 → §3.3.3 参照

**検証:** Phase A 完了後、スモークテスト（15式）で ok_count 増分と wall_time を計測。探索空間増に対し beam=1200 で許容範囲か確認。

### Phase B: 定数・パラメータ戦略の強化（期待効果: 中〜大）

方針2に基づき、**記号定数のハードコードは行わない**。`Param(C)` 最適化で $0.5$, $3.14$, $2.72$ 等の近似値を獲得する。

#### B-1. 複数 tunable パラメータの同時シード
- 現行: 複雑度1に `Param(C)` 1つのみ
- 改善: 複雑度1に `Param(C0)`, `Param(C1)`（必要なら `C2`）を追加（最大2〜3個、beam で制御）
- **根拠:** 係数 $A \cdot f(x)$ と指数・分母係数を同時に数値最適化可能に

#### B-2. Param 初期値の多様化
- 単一初期値 `1.0` ではなく、候補生成時に $\{0.5, 1.0, 2.0, 3.0, \ldots\}$ 等から選択、またはレベルごとにランダム初期化
- $1/2 \to 0.5$, $\pi \to 3.1$ 付近への収束を促進

#### B-3. `recognize_constant` の活用（数値近似のシード化）
- データから推定したスカラー（例: 係数の最小二乗推定値）を `Param` の初期値として注入
- 記号化（`Pi`, `E` ノード）は不要。数値がそのまま初期値になる

**検証:** 全体 ok_count の増分。個別式の定数が $0.5 \pm 0.01$, $3.1 \pm 0.1$ 等に収束しているかをレポートに **参考情報** として記録（合格判定には使わない）

### Phase C: 定数最適化の改良（期待効果: 中）

#### C-1. 真の Levenberg-Marquardt への置換
現行 `optimizer.rs` はコメント上 LM だが、実装は簡易勾配降下 + $\lambda$ スケーリング（最大20反復）。

改善:
- $(J^T J + \lambda I) \delta = -J^T r$ を解く LM ステップ
- 反復上限 **80**（cursor デフォルト案）
- 収束判定: RMSE 相対変化 $< 10^{-10}$

#### C-2. 多スタート最適化
- Pareto front 上位候補に対し、パラメータ初期値を $\pm 10\%$ 摂動して再最適化
- 局所解による partial 止まりの脱出（全体回収数向上に寄与）

#### C-3. 複数 `Param` の連成最適化
- 現行は全パラメータを同時に更新するが、ヤコビアンは有限差分のみ
- 解析的勾配は将来課題。まずは $\epsilon$ の適応制御

**検証:** 全体 ok_count の増分（partial → ok への昇格数をサブ指標として記録）

---

### Phase D: 探索戦略の調整（期待効果: 中）

#### D-1. MAX_COMPLEXITY = 7（確定）
- 複雑度7は Gaussian・ローレンツ因子等に必要
- 高変数式（$\geq 6$ 変数）ではメモリ・時間対策として complexity 上限を動的制限するオプションを検討

#### D-2. 二段階探索（Refinement Pass）
```
Stage 1: BFS（構造探索、complexity ≤ 7）
Stage 2: Pareto front 上位 K=5 候補に対し
         - 定数再最適化（Phase C、多スタート）
         - 単純代数簡約（Times(v,v) → Square(v) 等）
```

#### D-3. Beam スコアリングの見直し
- 現行: $\text{score} = \text{RMSE} \times (1 + \lambda \cdot \text{complexity})$
- 改善案: 低複雑度候補にボーナス、または複雑度帯ごとに beam 枠を配分（complexity-aware beam）
- cursor デフォルト: `beam_width=1200`, `complexity_penalty=0.08`

**検証:** 99式全体の ok_count と wall_time を記録（first_AI 比は参考）

# Phase F: 速度改善計画（2026/07/04）

**ステータス:** 承諾待ち（コーディング未着手）

## F.1 背景 — 深刻な速度低下

`I.12.1`（2変数）1式を first_AI と同一パラメータ（complexity=6, beam=1000）で実行したところ、以下の桁違いの遅延が発生した。

| Level | first_AI | cursor | 倍率 |
|-------|----------|--------|------|
| Level 4 | 約0.9秒 | 約126秒 | ~140x |
| Level 5 | 約11秒 | 約2246秒（37分） | **~200x** |
| Level 6 | 約38秒 | 完了せず | — |

3式スモークすら現実的に完了せず、全99式ベンチマークは実行不可能な状態。

## F.2 根本原因（コード精査により特定）

### 原因1（最大）: 複数 Param シードがフィンガープリント重複除去を無効化
- `bfs.rs` の Level 1 種まきで、初期値 $[0.5, 1.0, 3.0]$ の Param を **3個** 生成している。
- フィンガープリントは式をプローブ点で数値評価して重複判定するが、Param 評価に `initial_value` を用いるため、`Param(0.5)`・`Param(1.0)`・`Param(3.0)` は**別フィンガープリントとなり重複除去されない**。
- 構造的に同一の「調整可能定数」が3つの別物として残り、二項結合のたびに $3^{(\text{Param 部分木数})}$ で候補が指数増殖する。しかもこれらは LM で同じ値に収束する冗長計算。

### 原因2（大）: BFS 内 LM 反復が 20 → 80 で4倍
- `optimizer_max_iters = 80` により、Param を持つ全候補の定数最適化コストが first_AI の4倍。
- 1候補あたり概ね $\text{max\_iters} \times n \times (m+2)$（$n$=データ点数, $m$=Param 数）。原因1で $m$ も増大し、さらに悪化。

## F.3 修正方針（今回対象: 方針1・2のみ）

> 方針3（フィンガープリント側での Param 正規化）と方針4（Pow 除外）は今回は行わない。

### F-1. Param シードを1個に戻す（原因1の解消）
- `config.rs`: `param_seed_inits: vec![0.5, 1.0, 3.0]` → `vec![1.0]`（実質1個）。
- 初期値の多様性は **末尾 refinement pass の多スタート** で担保する（既に `refine_constants_multi(..., n_starts=3)` が実装済み）。
- これにより Level 1 の Param 種が1個となり、フィンガープリント重複除去が正常に機能。候補の指数増殖が解消される。

### F-2. BFS 内 LM 反復を削減（原因2の緩和）
- `config.rs`: `optimizer_max_iters: 80` → **25**。
- BFS 探索中は「概ね合っている候補を安く篩い分ける」ことが目的。精密化は末尾 refinement pass に委譲する。
- refinement pass 側は現行の `optimizer_max_iters` を使うため、そちらの精度を保つには F-2 で BFS 用と refinement 用の反復数を分離する必要がある。

#### 実装詳細（反復数の分離）
- `SearchConfig` に `refine_max_iters: usize`（refinement pass 用）を追加。
  - `bfs_max_iters`（＝現行 `optimizer_max_iters` を BFS 用に流用）＝ **25**
  - `refine_max_iters` ＝ **80**（末尾 refinement のみ高精度）
- `run_refinement_pass` は `refine_max_iters` を使用、BFS ループ内 `refine_constants` は `optimizer_max_iters(=25)` を使用。

## F.4 変更ファイル

| ファイル | 変更内容 |
|---------|---------|
| `src/config.rs` | `param_seed_inits` を `vec![1.0]` に。`optimizer_max_iters` を 25 に。`refine_max_iters: 80` を追加（`cursor_default` とビルダー） |
| `src/engine/bfs.rs` | `run_refinement_pass` で `config.refine_max_iters` を使用するよう変更 |

- 演算子（Square/Cube/Pow）、LM 本体、Pareto 構造は**変更しない**。

1. `cargo build --features python,full-math` / `maturin develop` でビルド確認。
2. **単発検証:** `I.12.1` 単式を実行し、各 Level の処理時間が first_AI 並み（Level 5 が数十秒オーダー）に戻ることを確認。
   - 合格基準: `I.12.1` 全体が概ね **5分以内** に完了し、RMSE < 1e-4 で回収。
